## Checked and found sound

These are narrow static conclusions, not a passing test gate or approval of whole packages.

- **Approval settlement and action tokens:** `store.SettleApproval` uses a conditional pending-row UPDATE, so competing browser/notification/sweep decisions have one database winner. `UseActionToken` consumes a hash-bound, expiring token with a conditional UPDATE; `actions.Redeem` checks the selected action against its stored scope. `approvals.Decide` enforces notification restrictions and dangerous confirmation on the server, assuming the classifier assigned the correct risk (C03).
- **Hook termination:** the PermissionRequest client has an overall deadline, bounded create/poll calls and a failed-poll give-up interval. Expired/superseded approvals produce no hook decision; allow output contains no permanent permission update. Startup supersedes old hooked pending approvals in the scanned set. This is not a finding of an unbounded hook wait.
- **Approval/job callback ordering:** `SetApprovalWaiting` rereads pending approvals under the job mutation lock rather than trusting the callback's boolean. The tick can clear a stale `needs_you/approval-tool` when nothing remains pending. This closes the ordinary out-of-order requested/settled callback case; it is not a comprehensive session-reuse audit.
- **Ordinary merge preconditions:** `landing.checkMerge` rejects a protected base, a main checkout on a different branch, and known tracked changes in that checkout. Successful dirty-worktree inspection rejects uncommitted job work. Teardown does not request force removal of a dirty worktree, and merged-branch deletion uses `git branch -d`. I have not established atomicity across concurrent landing operations or outside Git writers.
- **Review defaults:** reviewer jobs explicitly disable their own review gate, preventing recursive reviewer creation. An absent verdict counts as changes. The read-only reviewer restriction is explicitly documented as prompt-only; Codex still receives workspace-write. I did not report that documented limitation as a newly discovered enforcement guarantee.
- **Normal pause paths:** the Stop hook returns an allowing reply while paused. The normal launch/dispatch/retry/restart, poker and job-schedule paths contain pause checks; scheduled jobs remain due while held. C08 is an additional automatic prompt path those checks do not cover.
- **Routing and browser identity:** the pure `routeJob` decision is lead-first, with the documented exception that an orchestrator-origin terminal outcome reaches both its lead and the orchestrator. No-lead work falls back to the orchestrator. Since-you-left storage keys include the validated browser ID, so phone and desktop records are separate. This does not certify event replay or complete source counts.
- **First-run ordering and lazy connection:** `serve` completes the locked setup phase before connecting herdr or creating the agent services, except for explicit preconfigured/no-auth modes. `Lazy.Ready` and `Set` coordinate readiness under the mutex and publish the client atomically; the ordinary registration/connection race does not lose a wake-up.
- **Successful spend persistence:** `ApplySpend` commits totals, daily rows, turns and cursor state in one transaction. The defect in C10 is the in-memory handling of a failed transaction, not separation of those successful database writes.
