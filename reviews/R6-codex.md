## Checked and found sound, with limits

- **Head changes and Land pinning:** `accept.go:342–364` rejects evidence if HEAD changes during a run and schedules another check. The HTTP Land handler requires `expected_head` for merge/PR (`internal/httpd/landing.go:138–147`); `land.go:327–343` checks it separately from the evidence override. `internal/landing/land.go:53–64,231–241` uses the pinned commit as the actual merge/push source. Thus override does not authorize a different head on this path. RequestLand's head read still ignores errors (`landrequest.go:67–70`), and the lower-level API permits an empty head; those paths are not as strong as the HTTP contract.
- **Check restart and bounds:** `tickChecking` restarts checking jobs after a new server instance; individual commands have a timeout and process-group kill (`accept.go:381–395`). Only failed checks increment `CheckRounds`; repeated HEAD movement reruns without spending that budget, so the configured round cap does not bound a continuously changing checkout. Early read/command errors go to the human. No-check git jobs become unverified; non-git, reviewer/fix and standing-agent jobs explicitly bypass acceptance (`accept.go:144–149,250–263`). Do not interpret their Done as checked acceptance.
- **Needs-rebase arithmetic:** `internal/landing/git.go:255–269` computes behind against the current base branch, not merely the original recorded base commit. Merging that base into the work branch can clear the condition; there is no inherent permanent needs-rebase loop from retaining BaseCommit. The lost fix handoff in C11 is separate.
- **Budget accounting scope:** `budgets.go:152–215` aggregates descendant measured dollars/tokens and turns; time is parent wall time, including blocked time. Spend cursor recovery is repaired as noted above, and `meter.go:265–289` retains previously observed sessions. Rollup stops at five levels and excludes reviewers/fixes; normal default delegation depth is three (`delegate.go:55–63`). Unknown usage contributes no dollar/token enforcement, so an unmeasured engine with only those limits is not bounded by them; a configured time/turn cap remains necessary. No runtime claim is made about transcript/session capture completeness.
- **Prose and spinning:** `decide.go:93–106,117–134` respects declared/terminal/recovery states and checks MaxNudges before selecting the prose-specific refusal. Prose refusals share the ordinary three-nudge streak; they do not have a separate infinite refusal loop. Spinning requires 30 calls over ten minutes plus repetition and no observed progress; `spinning.go:265–305` exempts recent tree changes, unique edits/commits and changed failing-test sets. It still cannot distinguish useful repeated external observation from futile polling. `:423–440` notifies once per stuck spell; its prompt is not charged to the Stop nudge streak, and changed progress can begin another spell. These are heuristic limitations, not evidence of a hard-stop guarantee.
- **Wake recovery and pause:** blocked wake metadata is durable; `waits.go:220–249` polls due times and terminal dependencies after restart, and `:288–290` defers waking during pause. Fleet-limit holds are not checked there, so a due blocked wake can still send work during an engine hold. Dependency wakes also lack the time-wake path's declaration identity check (`:295–297`). Recheck counts reset on a fresh running-to-blocked declaration (`protocol.go:355–356`), so the ordinary wake/reblock sequence does not accumulate to the advertised three-recheck reminder. These boundaries need focused follow-up beyond C09.
- **Policy matching and lifetime:** `policy.go:281–333,405–429` requires a matching rule for every parsed simple command and anchors its glob, with spaces intentionally matched by `*`. Substitutions, eval and file-output redirects are refused. Environment prefixes are retained in policy matching, so `FOO=x go test …` does not silently match a plain `go test *` rule. Job rules are loaded only while scope reports the job live (`:502–512`); dangerous calls are excluded. Lexical `..` and sibling-prefix escapes are rejected, but symlinks are not (C03).
- **Batch and restart approvals:** `approvals.go:503–537` uses the explicit supplied IDs, so a new approval arriving during the batch is not swept into consent. Conditional per-row settlement protects competing decisions; batches can partially settle if a row changes after validation, rather than being transactional. Restart grace is bounded at 150 seconds and unpolled hooks are superseded (`:638–650,694–705`). A human can still allow a pending card before its hook reconnects; if the hook is gone, no command executes from that database answer alone, but “allowed” is not proof the hook received it. No delivery acknowledgment is implemented by this grace mechanism.
- **Phone paths:** inspected decision-packet stale-state rendering, answer controls, rescue controls, voice-job readback and creation, and Remote Control capture. Voice creation requires an explicit Create after readback (`VoiceJob.tsx:147–159,189–197`); it does not auto-submit transcription. Remote URLs are restricted to an exact HTTPS Claude session shape (`remote_url.go:30–34`) and transcript fallback requires system/bridge_status records (`:125–137`). Pane-text capture, however, accepts a matching URL anywhere after the last startup header and is not proof that it belongs to the currently observed session; session changes during capture are not compared again before publication (`remote_control.go:165–187`). Browser behavior and actual engine banners were not exercised.

## Coverage limits

The deepest review was of the named acceptance, budget, hold, wait, approval-policy and landing/review recovery paths. This was not a complete security re-audit of every R5 security finding or every phone component, nor a concurrency/race-detector run. In particular, concurrent external Git writers and concurrent Land operations, shell grammar beyond the concrete guard case, complete transcript metering, remote session churn, long pending queues, and browser accessibility/layout remain unverified. The invariant checker is a diagnostic, not a repair mechanism, and its existence does not establish that every wait can end.

Main at `96f6ea6` is not fit to tag: human-only gates can still be escaped, acceptance can certify uncommitted test inputs, and directory-scoped approval can authorize edits outside its intended subtree. The single biggest remaining risk to “never silently stops, never done-on-paper” is that authoritative gate/hold/evidence dispositions remain separate from loosely permitted job-state transitions and non-durable follow-up actions, allowing both false completion and lost recovery ownership.
